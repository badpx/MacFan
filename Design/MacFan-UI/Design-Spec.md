# MacFan UI 设计规范

设计方向：Quiet Clarity / 安静地，看见每一刻。

本规范对应已实现的 AppKit NSPopover + SwiftUI 原生界面。设计原型中的数据来自用户截图，为静态演示；实际应用从监控模块读取实时数据。原生界面快照可通过 debug 模式 --ui-snapshot 生成。

## 设计理念

MacFan 的价值是快速查看系统，而不是占据注意力。将原先密集的菜单行改为 384 pt 宽的轻量弹出面板，通过分组、数字字号与留白建立阅读顺序。CPU / GPU 并列，内存 / 磁盘用真实比例条，温度 / 风扇成组，网络明确分为下载与上传。

弹出面板保留「系统概览 / 菜单栏设置」两个标签页：概览完整展示七项读数；配置标签页控制菜单栏显示指标，并提供开机自启动开关。仅移除右上角设置图标，在原位置显示「每 2 秒更新」，不影响标签页导航。默认设计样例沿用截图选择：CPU、内存、温度、网络；实际升级必须保留用户已保存的选择。

中性色构建层次，青绿色标记正常比例与选中状态。温度和内存过高时，读数以醒目的橙色强调，随热度连续提高颜色强度 / 饱和感，延续当前实现的渐变反馈，不拆成固定颜色档位。异常同时提供明确文字，避免把 76% 内存占用或 0 RPM 直接解释为故障。

## 尺寸与布局

所有设计值以逻辑 pt 为准，原型 1 CSS px 对应 1 pt，PNG 按 2× 像素输出。

| 元素 | 规格 |
| --- | --- |
| 主面板 | 标准宽度 384；小屏 / 辅助字号增大时允许适配 |
| 外圆角 | 18 |
| 面板内边距 | 20 |
| 内容卡片 | 圆角 12，内边距 14，双列间隔 10 |
| 分组距离 | 16；组标题与内容间距 8 |
| 标签切换 | 高 34，内边距 3，选中块圆角 7；概览与配置位于同一面板 |
| 配置项 | 七项指标开关；开机自启动置于配置页下部，退出位于公共页脚 |
| 分隔线 | 1 pt，中性颜色 |
| 比例条 | 高 4，圆角 3，无描边 |
| 菜单栏 | 使用系统真实高度，设计预览栏高 36 仅用于展示 |
| 阴影 | 0 / 12 / 32，黑色 8%；近场 0 / 2 / 5，黑色 3% |

面板锚定菜单栏状态项，优先靠屏幕右侧适配。面板本身不用 macOS 主窗口的红黄绿控制按钮。打开面板后不改变菜单栏占位宽度；读数使用固定数字槽位，避免刷新时横向跳动。

屏幕可用高度小于面板自然高度时，面板总高限制为 visibleFrame 可用高度减去菜单栏及上下安全边距；固定顶部标题与标签区、底部操作区，内容区滚动。原型为了展示全部设计内容使用自然高度，正式 App 需实现此屏幕适配行为。

### 连续热度颜色

温度与内存分别根据自身数值独立计算热度，不能共用一个全局告警状态：

- 温度低于 75 °C：正常文字色；达到阈值后，h = clamp((T − 75) / 10, 0, 1)。
- 内存低于 80%：正常文字色与青绿比例条；达到阈值后，h = clamp((M − 80) / 10, 0, 1)。
- h 从 0 连续增加到 1 时，在 heat.start 与 heat.end 之间插值；超过区间上限时饱和，不继续加深。例：温度 75 / 80 / 85 °C 分别对应 h = 0 / 0.5 / 1；内存 80 / 85 / 90% 同理。
- 温度的数值和单位一起着色；内存的容量数值、单位、已用百分比和占用条使用同一热度色。标题、可用容量和大面积卡片背景保持中性，避免整块背景抢夺注意力。
- 每次 2 秒数据刷新同步更新热度，不闪烁、不呼吸；文案可以按「偏高 / 过高」分级，但颜色不能因此变成两个固定色值。
- 浅色采用较深橙色以保证小字可读，深色采用明亮橙色；降低透明度或降低对比不是告警表达方式。颜色调深的同时仍须保持文字可读。

与现有代码的关系：MetricFormat.heatColor 延续原 AppDelegate.applyMenuTitle 的 NSColor.systemOrange.blended(withFraction: h, of: .systemRed)，因此实际不只是改变饱和度，也包含从橙到红的色相变化。本规范保留这种按 h 连续增强的语义；上表是设计稿为浅深色可读性调整的橙色端点，原型用 sRGB 插值。原生界面已继续使用系统色混合；后续修改仍需检查真实系统外观下的对比度，不能用两档静态 warning / critical token 替代 heat。当前菜单栏数字维持系统标签色；热度强调应用于弹出面板，不擅自扩大为整个菜单栏染色。

## 字体与图标

| 层级 | 字体与大小 | 用途 |
| --- | --- | --- |
| 品牌 | SF Pro 17 / Semibold | MacFan |
| 核心数据 | SF Pro 30 / Medium；行高 38 | CPU / GPU |
| 次级数据 | SF Pro 24 / Medium；行高 32 | 温度 / 风扇 |
| 网络数据 | SF Pro 22 / Medium；行高 29 | 下载 / 上传 |
| 正文 | SF Pro 13 / Regular 或 Medium | 设置、容量 |
| 标签 | SF Pro 12 / Medium | 指标名、分段控件 |
| 辅助 | SF Pro 11 / Regular | 单位、说明、刷新周期 |
| 中文 | 苹方，随系统字体回退 | 同级保持相同字号 |

数值采用 monospaced digits；单位独立排版、弱化但保持对比。CPU 与温度保留一位小数，GPU 在设计稿统一为一位；内存已用量一位小数，百分比整数；网络单位自适应 B/s、KB/s、MB/s。不引入仅凭字符串解析得到的伪精度。

原型使用 Lucide 线性图标，正式 App 使用语义对应的 SF Symbols（cpu、memorychip、internaldrive、thermometer.medium、fan、arrow.down、arrow.up）。图标 16 pt，Regular，品牌 22 pt。无独立点击行为的图标不抢占焦点。

## 数据与状态

| 情况 | 呈现和行为 |
| --- | --- |
| 正常 | 数值以主文本色显示，青绿只编码比例 |
| 风扇运行 | 仅显示所有风扇的算术平均转速，整数 RPM；正常状态不显示底部说明，仅显示数值与单位，不显示 F1 / F2 |
| 风扇停转 | 两个风扇有效读数都为零时显示 0 RPM；不显示底部说明，通过 0 RPM 表达停转 |
| 无风扇机型 | 只有已确认硬件无风扇时才显示「无风扇」 |
| 无法读取风扇 | —；显示「传感器不可用」，不推断为无风扇机型 |
| GPU 无数据 | —；「暂不可用」，隐藏对应比例条 |
| 网络入站计数异常 | 下载 —；「暂不可用」，上传读数继续显示 |
| 首次采样 | —；「采样中」，取得有效差值后显示数据 |
| 数据过期 | 保留最后值并标注「更新暂停 · 上次更新…」，不能继续宣称实时 |
| 温度 75–<85 °C | 橙色随 h 连续增强 +「温度偏高」 |
| 温度 ≥85 °C | 颜色达到渐变终点并保持 +「温度过高」 |
| 内存 / 磁盘 80–<90% | 数值与比例条随各自 h 连续增强 +「偏高」；内存文案不称为内存压力 |
| 内存 / 磁盘 ≥90% | 颜色达到渐变终点并保持 +「很高」 |
| 菜单栏空间不足 | 保留选择，提示部分指标暂时隐藏；空间恢复时自动恢复 |

以上温度、内存、磁盘阈值继承当前代码的起止值，并保留连续热度。磁盘目前也有同样的 80%–90% 热度逻辑，沿用内存计算方式；本次状态稿重点展示用户指出的温度和内存。温度不能笼统命名为「CPU 温度」：当前 Apple Silicon 实现取可读 HID 传感器最大值，Intel 使用回退传感器，因此标题使用「温度」；正常状态移除「传感器读数」辅助说明以缩短卡片，只在告警或读数不可用时显示状态提示。

风扇统计：两个有效读数 r₁、r₂ 的平均值为 (r₁ + r₂) / 2，计算后再四舍五入到整数 RPM；例如 1800 与 2200 显示 2000 RPM。0 是有效读数，0 与 2000 应显示 1000 RPM，不得排除停转风扇。单风扇机型使用唯一有效读数。已知双风扇却只读到一个时，不将该值冒充双风扇平均值，显示「— / 平均转速不可用」。菜单栏与弹出面板使用同一平均值，不再一处平均、一处最大值。Swift 实现已统一为此平均值口径；缺少任一读数时不会将剩余风扇的值冒充整体平均。

内存使用当前应用的计算口径，24.2 / 32 的剩余为 7.8；磁盘使用系统卷容量及重要用途可用容量，326 / 995 的剩余为 669。实现时从未舍入的原始值计算，最后一步格式化显示。不要将内存已用比例视为系统的 Memory Pressure。

## 交互规范

1. 点击菜单栏状态项打开面板；再次点击、点击外部或按 Esc 关闭。打开时刷新，随后维持现有 2 秒刷新。桌面演示原型仅模拟可视部分，不接管系统快捷键或系统设置。
2. 保留「系统概览 / 菜单栏设置」标签，在同一面板内切换；右上角仅显示「每 2 秒更新」，没有设置图标按钮。按 Esc 关闭面板。
3. 开关立即更新菜单栏预览并持久化。概览的七项指标不因此消失；全关时恢复风扇图标。隐藏标签页中的控件从键盘焦点顺序移除。
4. 菜单栏数据顺序沿用现有固定顺序；不足时按现有降级策略隐藏最右侧项。原型仅用最多四项模拟空间约束，正式实现必须测量真实可用宽度。
5. 开机自启动沿用系统授权机制。系统要求用户批准时显示「等待系统允许」，注册失败时恢复真实开关值并展示原因；不能只显示开启动画便声称已成功。
6. 退出保留已有确认流程，⌘Q 可用；取消回到原页。原型退出只关闭演示面板，可以重新打开，不会退出真实 App。
7. 开关移动动画 140 ms；不使用常驻旋转、脉冲或背景粒子。尊重减少动态效果；优先保证工具自身低占用。

## 可访问性与实现建议

采用系统文本及 monospacedDigitSystemFont；VoiceOver 按“指标、读数、单位、状态”朗读。指标不逐次强制广播，仅在用户查看或状态真正变化时提供更新。配置控件键盘可达，焦点环清晰，标签标明选中状态并支持方向键切换；退出对话框约束焦点并支持 Esc。

推荐保留 NSStatusItem 与现有采样层，使用 NSPopover / AppKit 自定义内容视图实现面板。可用 NSVisualEffectView 提供轻微原生材质，但读数区域保持稳定对比；减少透明度时使用此稿的实色底。避免引入重型 WebView 或额外高频定时器。

MetricReading 现已提供 MetricValue 结构化数值，覆盖百分比、容量、温度、平均转速与独立的网络上下行数据；原生卡片直接使用这些字段，不拆解本地化 menu 字符串。概览仅展示当前值，本提案未增加历史曲线、网络总量或无来源的硬件型号。

验收重点：浅深色对比、长文案和大字号、2 秒更新无数字跳位、初次采样和异常读数、单 / 双风扇、菜单栏空间不足、退出确认及登录项真实状态。
